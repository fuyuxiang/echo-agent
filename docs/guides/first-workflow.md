# 第一个 Runtime 工作流

**适用范围：独立 Runtime。** 本页演示从只读任务开始，逐步使用文件与长期信息。先完成[快速开始](../getting-started/quickstart.md)，确保模型和入口已经可用。

## 1. 准备可控的输入

在当前 Runtime 允许读取的目录中准备一份 Markdown 或文本文件，包含几条可核实事实。不要以敏感业务资料作为首次验证内容。

发送任务：

> 请读取我指定的说明文件，只根据原文列出三条事实，并为每条附上原文依据。资料没有提到的信息请明确说不知道。先不要修改文件。

提供真实路径，并确保路径符合当前工作区与文件策略。若工具没有出现，检查工具是否启用、当前档位是否包含文件读取；若被拒绝，处理访问范围，而不是要求模型绕过限制。

## 2. 检查证据与结果

核对工具确实读取了目标文件，三条事实可以从原文找到，模型没有把常识当作资料中的内容。这个步骤同时检查文件工具、结果反馈和上下文使用。

## 3. 按需生成文件

继续要求将已核对内容整理为 Markdown，并指定允许的输出位置。写入需要对应工具和权限，审批时检查目标路径。完成后读取实际文件，核对正文与保存位置。

如果要求可下载的报告或附件，应使用产物交付流程。超长工具输出的临时保全引用不是正式交付物。

## 4. 区分历史、记忆与知识

| 需要 | 使用方式 | 如何验证 |
| --- | --- | --- |
| 继续讨论当前文件 | 继续同一会话 | 追问能对应原文与前文 |
| 保存稳定偏好 | 使用记忆功能，并指定适用范围 | 查看实际记忆条目和来源 |
| 反复检索多份资料 | 导入知识库并完成索引 | 检查索引状态、检索来源与片段 |

后台整合有触发条件，不会把每句聊天立即变成长期事实。更新资料后应检查知识索引，而不是只让模型“记住新版本”。

## 5. 从手动任务转为自动化

只有在单次运行结果稳定后，再配置消息通道或定时任务。定时任务需要明确输入、执行目录、模型、工具授权、输出和失败处理。先手动触发一次并核对结果，再交给调度。
