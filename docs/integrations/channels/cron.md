# Cron Channel

**适用范围：独立 Python Runtime。** 桌面端操作见 [Desktop 使用指南](../../desktop/index.md)。

Cron 通道通过定时任务触发 Agent 执行，无需外部消息输入。

## 单次提醒与原始附件

普通提醒支持直接投递固定文字和原始附件，无需在触发时调用模型。聊天中指定具体日期、时间和需要重发的文件即可；创建回执会区分“单次执行”“重复执行”和“附件待关联”。具体日期默认创建单次任务，不会隐式变成每年重复提醒。

`cronjob` 工具使用 `at`（带 UTC 偏移的 ISO 时间）和 `delivery_text` 创建固定提醒，使用 `attachment_ids` 绑定当前会话已保存的原件。`update` 可在原任务上修改时间、文字或附件。研究、日报等需要 Agent 执行的任务继续使用 `command`，周期任务使用 `schedule`。

文件和文字可以分别发送。用户要求重发尚未关联的文件时，工具可设置 `await_attachment=true`：同一会话内，前后十分钟窗口中只有一个文件、一个待关联任务，且后到文件没有随附文字指令时自动补齐并回执；有多个候选时需要明确指定，系统不会猜选。超过窗口仍可通过附件编号手动更新任务。

原件保存在工作区 `data/attachments/`，附件清单按会话隔离，独立于可清理的媒体缓存。正文解析失败不影响绑定或发送原件；`attachment_list` 查找原件，`read_document` 读取正文，`send_file` 发送原件。备份工作区时应包含该目录。附件清单使用本地索引，历史原件在升级时自动导入。

默认每个工作区最多保存 1024 MB 原件；未被提醒引用的文件保留 30 天，在后续访问清单或保存文件时清理。`attachments.max_mb` 和 `attachments.retention_days` 可调整此策略。暂停中的提醒、未来提醒及待投递记录会保护其附件，清理和容量回收都不会删除这些文件。空间不足会明确说明“原件尚未持久保存”，不会声称保存成功。用户可要求删除原件，系统通过 `attachment_delete` 执行；有任务引用时应先解除关联或取消任务。删除原件不删除历史对话和已提取正文。

固定提醒的文字和每份附件分别保存投递意图及渠道回执。微信会话暂不可用时沿用投递恢复机制；已确认送达的部分不会因另一份附件失败而重复发送。发送结果不明时保留待核对状态。暂停、删除或修改提醒后，旧投递意图不会在重启或会话恢复后继续发送；恢复任务只安排之后的执行。管理界面分别展示调度状态和渠道回执，可停止已触发提醒的待补发内容。修改普通任务不会新增无人值守权限，改名保留原有授权，修改内容后须重新授权。

## 概述

Cron 通道不是传统的"聊天"通道，而是一个事件注入机制。它按计划时间向 Agent 发送预定义消息，触发自动化工作流。

## 配置

```yaml
channels:
  cron:
    enabled: true
```

## 创建定时任务

### 通过 CLI

```bash
echo-agent cron list
echo-agent cron authorize <job-id>   # 需先停止服务
echo-agent cron revoke <job-id>      # 需先停止服务
```

### 通过 Agent 对话

Agent 可以通过 `cronjob` 工具自行创建定时任务：

> "每天早上 9 点给我发送天气预报"

也可以给已存在的任务补授权或撤销授权：

> "授权定时任务 148fb4a4b9"

### 通过 Dashboard

Dashboard Cron 页面支持可视化管理定时任务。

## 授权机制

新创建的 Cron 任务默认未获授权，任务仍会按时触发，但其中的写文件/执行命令等特权操作会被拒绝。这是安全设计：

- 防止 Agent 在无人值守时让定时任务执行高风险操作
- 授权按单个任务签发，三条路径：对话里说「授权定时任务 `<id>`」、Dashboard 定时任务页勾选、或停止服务后运行 `echo-agent cron authorize <id>`
- 授权与任务内容绑定：修改指令、频率或投递目标后授权自动失效，需要重新授权（改名和暂停/恢复不会）

详见[定时任务指南](../../guides/scheduled-jobs.md)。

## 输出路由

Cron 通道本身没有"发送"能力，投递目标记在**每个任务**上，不是全局配置 —— 配置中没有 `gateway.deliveryRoutes` 这样的路由表。

任务载荷中的两个字段决定输出去向：

| 字段 | 说明 |
|------|------|
| `deliver_channel` | 目标通道名，如 `telegram` |
| `deliver_chat_id` | 目标会话 ID |

两者留空时回落到任务的 `channel` / `chat_id`。用 `cronjob` 工具或 Dashboard 创建任务时指定即可。

## 常见问题

**任务创建了但不执行？**
- 检查是否已授权：`echo-agent cron list`
- 确认 Gateway 正在运行

**时区问题？**
- Cron 表达式使用系统本地时区
