# 任务、会话与权限

**适用范围：桌面端。** 任务描述要完成的目标；会话保存与该目标相关的交互和执行记录；工作区提供实际文件范围。持续补充同一个目标时使用原会话，开始无关工作时新建任务。

## 描述一个可验收的任务

任务至少说明四件事：输入是什么、允许处理哪些内容、交付什么、如何判断完成。例如：

> 阅读当前目录中的三份会议记录，汇总已确认的决定和未完成事项。生成“会议汇总.docx”，每个事项注明来源文件。不要修改原始记录。

长期项目可使用项目与工作项组织任务。项目负责归类与共享背景，具体执行仍在会话中完成。改变工作目录前，应确认新目录与当前任务有关。

## 选择权限模式

| 界面选项 | 行为 | 适用场景 |
| --- | --- | --- |
| 请求批准 | 需要授权的操作交给用户确认 | 首次使用、新项目、需要逐项检查 |
| 自动判断 | 低风险操作自动批准，必要时询问 | 目标与目录已明确的日常任务 |
| 本任务免审批 | 常规工具操作不再逐次询问 | 已充分信任的任务 |

首页的模式只用于将要创建的任务；已有会话中的调整针对该会话。桌面端模式与 Runtime 的审批配置分别管理。

权限模式、已授权工作区和自动化任务授权共同决定可执行范围。“本任务免审批”不授予额外系统权限。Browser Use 的副作用确认、Computer Use 的明确任务授权和操作系统权限各有自己的检查。

## 查看执行过程

计划表达当前执行方案，工具活动记录实际操作，Diff 展示文件差异。三者用途不同：计划中的步骤尚未执行，工具成功也可能仍需要最终结果验证。

遇到权限请求，核对工具参数与目标路径。拒绝后可以要求只读分析、改用其他文件位置或先说明方案。工具失败时应查看错误原因，再调整依赖、输入或权限。

## 补充、暂停与恢复

在同一会话补充要求可以保留背景。Computer Use 支持“停一下”或 `/pause` 暂停，“继续保存”或 `/resume` 继续，也可点击“继续任务”。应用重启后的自动化任务保持暂停，加载历史本身不会恢复操作。

恢复前先检查已有成果，尤其是保存、发送、提交等操作的结果，避免重复执行。会话历史还支持回溯与分叉；分叉保留对话分支，不等同于撤销已经发生的文件或外部系统变更。

## 结束任务

核对最终产物、文件差异和验证结果；未完成项应明确说明。任务记录可继续用于后续迭代，重要输出应保存为实际文件。有关备份与恢复，见[数据管理](operations.md)。
