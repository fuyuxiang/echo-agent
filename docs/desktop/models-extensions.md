# 模型与扩展

**适用范围：桌面端。** 模型提供推理能力，MCP 提供可调用工具，Skills 提供工作方法，专家提供角色与分工。启用扩展后，实际调用仍受当前任务的权限和服务可用性限制。

## 配置模型

1. 打开“设置 → 模型”。
2. 添加连接，填写服务地址、接口类型和 API Key。
3. 获取或添加模型，执行连接测试。
4. 返回任务选择实际使用的模型，再用简单任务检查文本响应与工具调用。

自定义连接支持 OpenAI、Anthropic 及其兼容接口。接口兼容不等于所有模型能力相同：图片输入、工具调用、上下文窗口与流式输出均依赖实际服务。

个人连接默认要求 HTTPS。内置模型访问项目配置的远端 HTTP 服务；无需个人 Key 不代表离线，也不代表服务用量没有限制。用量统计为本机记录与估算，不等于服务商账单。

## 选择扩展机制

| 机制 | 解决的问题 | 使用前检查 |
| --- | --- | --- |
| MCP | 连接外部工具与业务系统 | 服务是否可达、凭据及授权范围 |
| Skill | 复用专业方法与任务流程 | 来源、适用场景、依赖能力 |
| Plugin | 安装一组扩展能力 | 安装来源、启用状态及受影响功能 |
| 连接器 | 为任务接入所选资料或服务 | 账号、数据来源与访问范围 |
| 专家 | 保存角色、指令与模型选择 | 职责、工作区和知识来源 |

从“专家·技能·连接器”管理相应能力。MCP 服务连接成功后，还应检查工具是否启用；技能可见不代表其需要的工具、命令或外部服务已经可用。

插件支持启用、禁用和按来源管理。卸载受管理安装包前，界面会列出受影响插件；外部来源可打开目录管理。失败时保留错误信息，可修复后重试。

## 排查模型或工具问题

先区分故障发生在哪一层：连接测试失败检查地址、Key 与网络；纯文本可用但工具失败检查模型工具能力与参数；只有某个扩展失败检查扩展服务、依赖与授权。不要通过反复更换全部配置来定位单一工具错误。

配置文件与凭据位置见[数据管理](operations.md)。能力原理见[工具、技能与插件](../concepts/skills-tools-plugins.md)。
