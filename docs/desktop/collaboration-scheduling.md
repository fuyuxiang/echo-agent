# 专家团与定时任务

**适用范围：桌面端。** 专家团用于保存成员分工、讨论、工作与决定；定时任务按计划启动本机执行。两者均使用桌面端内嵌执行引擎。

## 创建专家团

从“专家·技能·连接器 → 专家团”创建，选择 1–8 名本地专家、模型和工作区，协调员自动加入。也可从会话团队创建；已经关联的团队会打开原专家团。

普通消息交给协调员；`@成员名`、`@全体` 或回复成员可确定收件人。建议先用只读讨论梳理目标，再发起需要工具执行的工作。只读讨论在执行引擎中限制工具权限。

“成员 / 工作 / 交付物 / 设置”分别用于查看职责、实际执行状态、工具生成的文件和配置。专家团模板只包含明确保存的成员、分工和模型，不包含聊天记录。

## 协作与决定

协调员可拆分任务并汇总成员结果。成员使用独立会话；同一工作区的执行工作串行，默认每个专家团最多同时运行两名成员。自动调用次数、派发深度和 Token 预算约束持续协作。

模型提出的决定需要用户确认，确认后才作为后续工作的共同依据。决定可更正、作废与恢复，并保留修订记录。成员记忆、共享决定和聊天历史是不同来源；清除成员记忆不会删除聊天或共享决定。

补充要求时优先回复对应工作消息，避免目标不明。暂停停止后续派发，准备中的工作保留；停止会取消运行与待汇总工作。重启中断的工作标为“需要检查”，应先检查已有成果再手动重试。

归档用于暂时退出活跃列表，可恢复；永久删除会清理专家团所属记录，个人专家、已保存模板与工作区文件保留。

## 创建定时任务

在定时任务界面配置目标、计划、工作目录、模型和权限，先手动执行一次，核对运行记录、结果与输出位置，再启用计划。

桌面调度器在应用进程中运行，电脑关机、休眠或应用退出时不能按时执行。需要长期服务时，可使用独立 [Runtime 后台服务](../operations/background-service.md)。桌面计划与 Runtime Cron 分别存储和管理。

运行记录区分排队、执行中、成功、失败和中断。计划到期不等于任务成功；无人值守任务应避免依赖临时弹窗或只有当前用户能完成的操作。配置通知或微信推送时，还需检查对应连接状态。

## 验收协作结果

检查各成员交付是否可用、引用是否可追溯、汇总是否覆盖原目标，以及失败或中断工作是否仍需处理。协作原理见[多 Agent](../concepts/multi-agent.md)。
