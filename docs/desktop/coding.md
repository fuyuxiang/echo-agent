# 代码工作台

**适用范围：桌面端 Echo Code。** 代码工作台把 Agent 对话与内嵌 Theia IDE 结合起来，提供文件树、编辑器、搜索、终端、Git、预览和变更审阅。

## 开始代码任务

1. 选择实际项目目录，确认工作区授权。
2. 打开代码工作台，检查文件树与当前 Git 状态。
3. 说明问题、允许修改的范围和验证命令。
4. 查看计划与执行过程，审阅文件差异，再核对验证结果。

示例：

> 修复表单重复提交问题。保留现有页面交互，只修改相关逻辑。先检查现有测试与未提交修改，完成后运行相关验证，并说明哪些情况已验证。

项目原有未提交修改应在任务前检查。Agent 生成的变更需要结合实际 Diff 审阅；不要仅凭文字回复判断修改范围。

## 理解工作阶段

工作台围绕分析、计划、实现、验证和交付组织代码任务。变更集用于汇总涉及的文件，验证记录说明执行过哪些检查，交付结果说明完成内容与剩余问题。阶段与检查通过情况应结合使用。

内嵌 IDE 提供交互式编辑环境，Agent 执行引擎负责推理与工具调用，宿主协调两者的工作区、变更和状态。IDE 终端使用当前系统用户身份；项目所需编译器、解释器、依赖和服务需自行准备。

## 验证与交付

| 检查 | 判断依据 |
| --- | --- |
| 修改是否符合范围 | 实际 Diff 与文件列表 |
| 是否保留原有工作 | 对照任务前 Git 状态和未提交修改 |
| 是否修复问题 | 相关测试、构建或可复现的操作结果 |
| 是否可以交付 | 产物、验证结果和未完成项一致 |

检查点和变更审阅有助于恢复与比较，但不能替代项目版本管理或完整数据备份。

## 断线与恢复

IDE 连接异常时，应用会尝试验证本地后端并恢复。若有未保存内容或保存状态不明，先保留页面并复制重要内容，再手动重新连接。切换项目会重新启动相应后端。

常见问题和日志位置见[故障排查](operations.md)。实现关系见[桌面端架构](../concepts/desktop-architecture.md)。
