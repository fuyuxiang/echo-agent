# 专家与团队项目

团队项目复用组织服务的账号、实时知识 scope、文档扫描、摄取、版本和检索。需要同步升级 `echo-agent-server`（迁移 `015_team_projects.sql` 、`016_project_creation_keys.sql` 、`017_project_task_identity.sql` 与 `018_project_workspace.sql`）；个人项目继续使用本机存储。

## 项目与协作入口

项目列表使用统一的“新建项目”，同时显示个人项目与当前账号可访问的共享项目。已关联的本机项目不会再显示一份重复的远端卡片；搜索和范围筛选覆盖整个列表。组织服务不支持项目接口时，个人创建与本机资料不受影响。

项目详情采用“概览 / 任务 / 资料与成果 / 动态”四个入口，右侧项目上下文可收起。概览显示需要处理的任务、真实执行状态和最近成果；底部输入框发起新任务。右上角“邀请”管理真人成员，AI 专家通过执行偏好配置。所有项目使用同一套详情，受邀项目首次打开时只建立本机关联，不复制远端正文。

共享项目的“问项目”独立于任务输入框，查看者无需配置执行模型也可查询项目进展、请求新成员简报及查看来源。回答与原文只在内存中保留；查询结束和打开引用时均核对成员权限与项目版本，账号切换、连接失效或依据更新后清除旧结果。问题草稿按账号与项目隔离，关闭窗口后可继续。

旧会话以稳定 ID 迁移为任务入口，已有工作项绑定的会话不会重复；原会话索引、正文、归档状态、原计划和能力配置保留。项目移入、分叉、移出与删除引用也同步维护统一任务。任务详情提供继续会话、说明、状态、验收和执行报告；移除本机任务仅移除项目引用，不删除实际会话。

已有任务共享后仍可从详情打开本机原会话，归档会话先恢复再打开；协作执行继续使用独立的公开执行入口。启动失败在当前任务详情说明原因，保留原状态与草稿，并可调整执行目录后重试。补充共享复用已有任务、资料和创建请求身份，上传恢复记录同时保留文档版本族，避免重复发布或覆盖现有协作关联。

新建项目仅名称必填，工作目录和项目说明可选，指令模板与执行偏好默认折叠。右上角“项目设置”编辑名称、说明、指令和执行偏好，明确保存才写盘；关闭未保存内容会确认。共享说明由管理员维护，本机指令与能力偏好保留独立范围，原备注和计划记录仍可读取。

首次共享明确选择任务和资料，原始个人会话、旧参与者备注、模型密钥与连接器凭证不上传。共享任务显示服务端最新状态；网络中断时保留关联并锁定编辑，避免产生一份可编辑的私人副本。新任务与输入框新发起的工作统一创建协作任务；公开执行报告共享给成员，附件仍走原文件授权、目录与权限校验。

资料页合并本机文件与已共享版本，关联依靠账号、文档与版本族 ID，不按文件名猜测。原私人文件仍标注“仅自己”；共享项目新添加的资料会提示成员可见。更新版本后保留旧本机副本，可在历史版本展开查看。

共享关联按组织账号写入本机项目数据，兼容旧版 `echoagent.team-publication.v1` 发布记录，不重复创建旧项目。发布进度继续保存在原有恢复记录中。新服务支持 `clientRequestId`，首次创建响应丢失后用原请求 ID 重试；旧版服务保留人工核对恢复流程。

服务端 `GET /api/v1/projects/capabilities` 返回功能版本。成员候选搜索只对项目管理员开放，限制搜索长度及返回数量，仅显示有效且尚未加入项目的组织成员。成员权限变更使用项目版本校验，负责人不可降权；移除、降权和账号切换继续遵循实时授权边界。旧服务支持原始项目接口时仍可用用户名邀请，不显示其不支持的搜索和权限调整。

新增接口：

- `GET /api/v1/projects/:id/member-candidates?q=...`：搜索可邀请成员。
- `PATCH /api/v1/projects/:id/members/:userId`：使用 `role` 与 `expectedRevision` 更新权限。
- `POST /api/v1/projects` 的可选 `clientRequestId`：按创建者与请求 ID 去重。
- `POST /api/v1/projects/:id/tasks` 的可选 `clientRequestId`：按项目、创建者与请求 ID 去重；重试返回原任务，不覆盖已有状态和说明。能力版本 3 返回 `taskIdentity: true`。旧接口保持兼容，新协作任务需要服务端升级。
- 资料上传响应附带 `familyId`，用于跨版本关联本机文件。数据库只增加身份映射表，不改写旧任务或运行记录。
- 任务状态 PATCH 仅更新显式提供的字段，避免清空说明和验收要求。

## 项目工作台流程

- 任务以真实会话状态显示运行、等待处理、暂停或待验收；一次执行结束不自动等于验收。暂停指定会话并等待原生确认，继续任务打开原会话及原工作目录。任务详情中的新任务输入框收起，避免把新任务误认为续写。
- 成果从实际会话文件与原生文档导出记录汇集，保留来源会话。预览读取实际文件；“用于新任务”先授权并复制到项目私有资产目录，待原生持久化成功后选择附件。相同路径的新版本保留独立副本。本机成果可明确“共享到项目”，上传前重新核对项目目录中的登记文件并恢复单文件授权；共享文件与任务附件使用各自的大小上限。远端文档读取与下载继续检查账号及成员授权。
- 动态合并本机操作、会话活动和共享事件。共享留言使用账号隔离的草稿与稳定请求 ID，响应丢失、切换标签后重试不会重复写入。查看者和不支持留言的旧服务没有提交入口。
- 本机项目决定支持记录、更正、作废、恢复和修订历史，只有有效决定进入新任务上下文。共享决定由成员提出、管理员确认与更正；修改使用版本校验，保留旧内容。
- 项目定时工作使用现有原生调度器，支持保存、启停、立即运行与执行记录。`Automation.projectId` 持久关联项目；每次实际执行重新读取本机项目指令、有效决定与任务状态，执行会话自动回到项目任务列表。该功能在本机运行，应用需保持在线；共享项目的本机定时工作不会绕过服务器授权自动读取私人数据。

能力版本 4 增加 `projectComments` 与 `decisionRevisions`。迁移 `018_project_workspace.sql` 新增留言去重索引和决定修订历史，保持旧任务与文档不变：

- `POST /api/v1/projects/:id/comments`：成员留言，按项目、账号与 `clientRequestId` 去重。
- 项目 snapshot 增加 `comments` 和决定的 `history`。
- `PATCH /api/v1/projects/:id/decisions/:decisionId`：显式修改内容、理由或状态，使用 `expectedRevision` 防止覆盖并发修改；作废内容可恢复，已替代内容不能直接重新启用。

## 能力与运行

- 专家模型复用应用有效模型目录；技能与连接器使用真实列表选择，显示用途、来源、停用或待授权状态。未找到的旧模型、技能路径和连接器引用保持原值，编辑其他设置不会清空它们。
- 技能发现、上级技能继承与工具允许/禁止规则默认收起；卡片标签单独折叠，不改变实际模型。内联 MCP 配置和自定义继承对象保留原定义，编辑器仅修改其拥有的字段。账号凭证仍由连接器和组织资源管理。
- 单专家和专家团成员使用同一个原生 `resolve_profile`。会话权限和记忆边界由宿主提供。专家团可以明确覆盖成员模型。
- 严格模型保留其内置运行格式和工具协议，同时应用专家指令、技能与工具限制；保存和恢复时保留运行格式身份。连接器范围在首次创建、恢复、配置更新及插件刷新时持续生效，应用内置的协作、项目知识和文档服务由宿主管理。
- 单专家创建时传递完整 ACP `agentProfile`，并在本机保留定义快照供恢复与继续任务使用。新会话创建去重包含定义哈希。
- 专家团模板保存明确的模型覆盖；新建成员的继承选择不会在保存模板时被固化。旧模板保留原固定模型行为。

## 成员与资料

项目管理员邀请已有组织用户，分配管理员、协作者或查看者。负责人不能被直接移除。组织成员与组织管理员不会仅凭组织身份得到项目内容。

项目知识使用独立的 team scope，并通过项目成员关系加入 `v_user_scopes`。用户权限不写入 JWT；移除成员影响项目 API、普通文档读取和通用检索。

资料通过原生已授权文件路径上传，在组织服务进行既有技术扫描与文档摄取。新版本未 ready 前继续使用上一有效版本。共享状态与可检索状态分别展示。

个人项目可显式发布为团队项目：只发布选中的工作项、文件与项目目标，保留个人会话和本机参与者备注。部分发布失败时保留目标项目，重试继续发布剩余内容。

发布目标、已成功内容和选择进度按组织账号与个人项目保存在本机；离开页面或重启后可以继续。创建请求的结果不明确时，先核对已有目标再继续，避免重复创建。文件选择、授权和上传各阶段均保持最初账号边界；单份资料的新版本只允许选择一个文件，批量发布部分失败后会刷新已成功的结果。

## 项目问答与接手

项目问答组合当前工作项、已确认决策、工作执行记录与当前有效文档。回答复用组织问答的生成和事实核验；未配置生成模型或核验失败时，展示有来源的摘录并明确标记信息不足。

问答结束前重新检查成员资格、项目版本、文档权限和当前版本。来源可再次授权读取原文。决策候选、有效决策和已替代决策分别保存，替代与版本校验在一个事务中完成。

接手操作在发送前以工作项版本校验完成责任转移，并在接手者的桌面使用新的独立执行。不会迁移原成员的进程、个人连接或登录状态。

桌面先完成模型、配额和执行资源预检，再进行责任转移与发送；失败会明确区分“尚未接手”和“已接手、启动未确认”。接手其他成员的工作或替换运行中的执行时会确认影响。团队项目支持编辑工作说明与验收要求、查看执行记录和公开报告、按工作项筛选，以及打开本机已有执行继续工作；其他设备上的执行仅展示共享报告。

每个项目执行会话绑定原组织账号和项目。继续发送与恢复会话前重新读取授权上下文；分支会话保留该边界。组织 MCP 注册包含账号代次，避免运行中的旧会话在账号切换后借用新身份。

专家团的实时补充也在保存与投递前检查项目权限；移除成员、降为查看者或切换账号后不能继续指挥旧项目运行。MCP 请求将原账号代次贯穿文档授权、知识查询与最终响应，避免在异步请求中重新借用当前账号。

运行结束后回写执行记录；成功执行将仍由该执行者负责、且未被更新的工作项转为待验收。晚到的结果不能覆盖已经移交或验收的工作。只有项目管理员可确认验收。

单专家执行回写当前回合的公开输出，过滤推理区块并按 session/prompt 隔离、去重和限长；专家团回写该请求的最终公开交付。执行记录作为历史报告参与项目问答，当前状态仍以最新工作项和已确认决策为准。来源打开前会检查项目是否已更新，避免将过期回答的摘录当作当前依据。

未同步的终态记录保留在本机 outbox，刷新原账号对应项目时重试，并提示共享进展可能不完整。文件成果由成员在“资料”中明确发布；本地生成不等于已共享。

运行登记使用本机日志记录请求身份及登记结果。未开始就取消的请求不提交终态；登记响应不确定时先核对服务端是否已有该运行，再结算结果。重试专家团请求会使用新的运行记录，保留旧尝试的报告与待同步内容。远端登记失败会执行与发送失败相同的本机清理，释放已申请的运行权限。

## 验证入口

- 桌面：`pnpm exec tsc --noEmit`、`pnpm test`、`pnpm build`。
- 新交互的真实浏览器验收：`pnpm test:ui:expert-project`（浅深主题、420/1280 宽度、选择与保存、首次共享及邀请）。
- 定向交互：`pnpm exec vitest run src/components/__tests__/TeamProjectsPanel.test.tsx src/components/__tests__/ExpertCapabilitiesEditor.test.tsx src/components/__tests__/ExpertEditorTransactions.test.tsx`。
- 原生：`cargo check --locked --manifest-path src-tauri/Cargo.toml --lib --tests`、`pnpm test:rust`；原生测试需要按 testing.md 准备隔离数据和 macOS 测试签名。
- 组织服务：`npm test`；`test/projects.test.ts` 覆盖 A/B 发布、C 加入与接手、资料版本、决策替代、访问撤销、运行幂等和晚到结果隔离。

HTTP 测试使用临时数据库和存储，不等同于真实企业环境部署验收。跨设备上线前仍需用同一服务实例和独立组织账号进行实机验收。

项目工作台专题验证：`pnpm test:ui:project-workspace`，覆盖三种尺寸、明暗主题、成果预览与复用、会话暂停、验收、留言和调度。浏览器使用生产组件与受控 IPC；服务端 HTTP 测试及 Rust 宿主测试分别验证接口和原生实现，不能替代真实模型、系统选择器或多设备验收。

真实账号与模型联调入口为 `pnpm test:project:native <程序> <账号配置>`，具体授权范围、私有模型资源和构建要求见 [开发与验收](testing.md#原生应用与真实模型)。验收同时核对实际文件、原任务来源、服务端任务与执行记录、真实调度时间和重启恢复，不将浏览器受控 IPC 作为该层的成功结果。

新建协作项目的知识范围可能晚于最近一次 bootstrap；首次执行只允许原生会话绑定对应、且服务端即时核验成员权限通过的那个范围，不能把任意范围加入本机缓存。模型配置 ID 与上游请求中的模型名分别保存，避免任务恢复时丢失组织提供方身份。

项目定时工作在保存启用配置前，按实际执行目录检查所选技能及其运行依赖。调度器兼容旧名称与项目路径引用，只能解析当前技能目录中的条目；目录或权限变化后的派发仍重新预检，不会直接加载外部传入的任意路径。
