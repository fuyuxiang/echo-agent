# 专家与团队项目

团队项目复用组织服务的账号、实时知识 scope、文档扫描、摄取、版本和检索。需要同步升级 `echo-agent-server`（迁移 `015_team_projects.sql`）；个人项目继续使用本机存储。

## 能力与运行

- 专家编辑器支持默认模型、技能、工具允许/禁止列表、技能发现与 MCP 引用/继承。账号凭证仍由连接器和组织资源管理。
- 单专家和专家团成员使用同一个原生 `resolve_profile`。会话权限和记忆边界由宿主提供。专家团可以明确覆盖成员模型。
- 严格模型保留其内置运行格式和工具协议，同时应用专家指令、技能与工具限制；保存和恢复时保留运行格式身份。连接器范围在首次创建、恢复、配置更新及插件刷新时持续生效，应用内置的协作、项目知识和文档服务由宿主管理。
- 单专家创建时传递完整 ACP `agentProfile`，并在本机保留定义快照供恢复与继续任务使用。新会话创建去重包含定义哈希。
- 专家团模板保存明确的模型覆盖；新建成员的继承选择不会在保存模板时被固化。旧模板保留原固定模型行为。

## 成员与资料

项目管理员邀请已有组织用户，分配管理员、协作者或查看者。负责人不能被直接移除。组织成员与组织管理员不会仅凭组织身份得到项目内容。

项目知识使用独立的 team scope，并通过项目成员关系加入 `v_user_scopes`。用户权限不写入 JWT；移除成员影响项目 API、普通文档读取和通用检索。

资料通过原生已授权文件路径上传，在组织服务进行既有技术扫描与文档摄取。新版本未 ready 前继续使用上一有效版本。共享状态与可检索状态分别展示。

个人项目可显式发布为团队项目：只发布选中的工作项、文件与项目目标，保留个人会话和本机参与者备注。部分发布失败时保留目标项目，重试继续发布剩余内容。

发布目标、已成功内容和选择进度按组织账号与个人项目保存在本机；离开页面或重启后可以继续。创建请求的结果不明确时，先核对已有目标再继续，避免重复创建。文件选择、授权和上传各阶段均保持最初账号边界；单份资料的新版本只允许选择一个文件，批量发布部分失败后会刷新已成功的结果。

## 项目问答与接手

项目问答组合当前工作项、已确认决策、工作执行记录与当前有效文档。回答复用组织问答的生成和事实核验；未配置生成模型或核验失败时，展示有来源的摘录并明确标记信息不足。

问答结束前重新检查成员资格、项目版本、文档权限和当前版本。来源可再次授权读取原文。决策候选、有效决策和已替代决策分别保存，替代与版本校验在一个事务中完成。

接手操作在发送前以工作项版本校验完成责任转移，并在接手者的桌面使用新的独立执行。不会迁移原成员的进程、个人连接或登录状态。

桌面先完成模型、配额和执行资源预检，再进行责任转移与发送；失败会明确区分“尚未接手”和“已接手、启动未确认”。接手其他成员的工作或替换运行中的执行时会确认影响。团队项目支持编辑工作说明与验收要求、查看执行记录和公开报告、按工作项筛选，以及打开本机已有执行继续工作；其他设备上的执行仅展示共享报告。

每个项目执行会话绑定原组织账号和项目。继续发送与恢复会话前重新读取授权上下文；分支会话保留该边界。组织 MCP 注册包含账号代次，避免运行中的旧会话在账号切换后借用新身份。

专家团的实时补充也在保存与投递前检查项目权限；移除成员、降为查看者或切换账号后不能继续指挥旧项目运行。MCP 请求将原账号代次贯穿文档授权、知识查询与最终响应，避免在异步请求中重新借用当前账号。

运行结束后回写执行记录；成功执行将仍由该执行者负责、且未被更新的工作项转为待验收。晚到的结果不能覆盖已经移交或验收的工作。只有项目管理员可确认验收。

单专家执行回写当前回合的公开输出，过滤推理区块并按 session/prompt 隔离、去重和限长；专家团回写该请求的最终公开交付。执行记录作为历史报告参与项目问答，当前状态仍以最新工作项和已确认决策为准。来源打开前会检查项目是否已更新，避免将过期回答的摘录当作当前依据。

未同步的终态记录保留在本机 outbox，刷新原账号对应项目时重试，并提示共享进展可能不完整。文件成果由成员在“资料与成果”中明确发布；本地生成不等于已共享。

运行登记使用本机日志记录请求身份及登记结果。未开始就取消的请求不提交终态；登记响应不确定时先核对服务端是否已有该运行，再结算结果。重试专家团请求会使用新的运行记录，保留旧尝试的报告与待同步内容。远端登记失败会执行与发送失败相同的本机清理，释放已申请的运行权限。

## 验证入口

- 桌面：`pnpm exec tsc --noEmit`、`pnpm test`、`pnpm build`。
- 定向交互：`pnpm exec vitest run src/components/__tests__/TeamProjectsPanel.test.tsx src/components/__tests__/ExpertCapabilitiesEditor.test.tsx src/components/__tests__/ExpertEditorTransactions.test.tsx`。
- 原生：`cargo check --locked --manifest-path src-tauri/Cargo.toml --lib --tests`、`pnpm test:rust`；原生测试需要按 testing.md 准备隔离数据和 macOS 测试签名。
- 组织服务：`npm test`；`test/projects.test.ts` 覆盖 A/B 发布、C 加入与接手、资料版本、决策替代、访问撤销、运行幂等和晚到结果隔离。

HTTP 测试使用临时数据库和存储，不等同于真实企业环境部署验收。跨设备上线前仍需用同一服务实例和独立组织账号进行实机验收。
