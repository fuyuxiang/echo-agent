# 客户端进程保护与异常恢复

代理终端的公共启动入口会检查前台和后台命令，禁止按名称批量终止进程，并保护客户端、已登记的基础进程和系统关键进程，防止通过 PID 误杀。进程身份由操作系统读取；基础进程租约绑定创建时间，避免 PID 重用后误保护其他进程。普通任务启动的服务仍可按明确 PID 停止。命令检查区分信号参数和目标 PID，允许信号 0 的存活查询及 PowerShell 的 `-Id:PID` 写法；条件、循环、重定向和命令替换中的终止操作同样接受检查。Here-document 的普通文本不会被当作命令执行，未引用文档内的命令替换仍会检查。

保护独立于自动批准模式。直接调用的脚本会进行有界检查，编码 PowerShell 命令、动态终止目标等不可核实操作会要求改用明文和明确 PID。这是常见误操作保护，不是任意代码执行的操作系统安全沙箱；外部原生程序、外部 MCP 或其他同用户进程不应被宣称已被字符串检查完全隔离。

Windows 监听 WebView2 的进程失败和浏览器退出事件：渲染进程退出先重新加载页面，浏览器进程退出或持续无响应则重建窗口。macOS 使用 Web 内容进程终止回调；可见且聚焦窗口有心跳兜底。后台窗口、系统休眠不计作心跳故障。事件去重，120 秒内至多自动恢复 3 次，失败后保留原生重试对话框和托盘入口。

新文档需要携带窗口代次与独立文档身份确认恢复。旧窗口、旧文档的回执不能结束新一轮恢复。窗口重建复用数据目录和健康的 Runtime，保留窗口大小、位置及隐藏状态。本机保存当前任务 ID；异常恢复时先从原生会话列表核验任务、目录和归档状态，再加载原任务历史，完成前不开放发送。普通启动保留首页；恢复时用户已主动导航则尊重用户选择，失效任务返回首页并给出说明。不重新发送原任务。引擎线程退出会自动重试初始化并加载原会话；重试有上限，可停止，也可手动重试。发送结果不确定的队列项仍暂停等待核对。

发行构建还启动独立看护进程，通过私有标准输入管道观察宿主死亡。Windows 验证看护进程不属于宿主的退出清理 Job；正常退出、升级和主动重启抑制自动拉起，退出失败则恢复看护。宿主崩溃重启也有滚动次数限制；恢复提示使用一次性标记，后续正常重启不会重复提示崩溃。开发构建、常规隔离验收模式不启用看护，避免停止开发服务器后应用被重新打开。

录音方面，系统声音的原生采集不会因界面重建而被停止。麦克风录音由失效的渲染器持有时，已有音频会保留并标记中断；恢复时根据实际 WAV 文件中的完整 PCM 帧修复长度、时长及样本数，包括已写入音频但尚未提交会议清单的分片；仅丢弃不足一个采样帧的末尾字节。无法承诺恢复尚在 JavaScript 内存中的音频尾段。格式损坏或超出限制的原文件会保留并报告错误。界面失效后的退出采用原生确认与保存流程，不等待已经消失的页面响应。

已接受的用户消息按顺序及时写入回放日志，模型文本仍可合并写入；写入失败保留重试。等待模型首个响应期间异常退出后，恢复界面应显示最后一条用户请求，并与实际聊天历史一致；显示恢复不代表再次派发该请求。

## 验证

- `pnpm test:stability`：编译并测试生产进程保护、恢复限流、看护管道协议、PCM 文件恢复和进程树回收代码。
- `cargo check --locked --manifest-path scripts/stability-check/Cargo.toml --target x86_64-pc-windows-msvc`：从其他主机检查 Windows 原生 API 类型，需要已安装该 Rust 目标。
- `pnpm test:stability:native`：构建独立小型 Tauri 验收程序；使用新建的系统临时目录，验证真实窗口重建、文档重载、宿主异常退出与外部看护重启后草稿保留，以及受控重启和正常退出不会误触发崩溃恢复。Windows 额外按当前 WebView2 环境的明确 PID 注入渲染进程和浏览器进程退出，并在终止前核验归属和创建时间。

原生验收不读取日常用户资料，不按进程名称结束进程。报告写入该临时目录的 `evidence.jsonl`；仅退出码、完整的恢复记录和草稿检查均通过时才报告成功。编译检查和单元测试不替代 Windows 原生故障注入。

完整客户端的强制退出、历史恢复及持续运行使用 [开发与验收](testing.md) 中的生命周期驱动。持续运行需分别记录墙钟、活动时间、锁屏/睡眠与采样进程范围；窗口恢复或有限时长观察不能替代休眠唤醒、全天负载和其他平台的验收。
