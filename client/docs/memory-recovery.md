# 记忆处理与可靠退出

聊天记录的最终持久化确认仍在所有会话收尾写入之后，并且需要会话 actor 结束。不能通过提前确认、丢弃 Runtime 或强制退出绕过保存失败。

退出时停止并等待当前会话的记忆后台任务取消，保留已有的提取检查点，再保存当前尚未提取内容的检查点和本地摘要。退出链路不执行记忆模型请求、embedding 或 dream。实际本地写入失败仍会保留 Runtime 并重试；关闭记忆后不再创建新检查点。

检查点放在工作区记忆目录的 `pending/`，按来源、会话进度和内容生成身份。同一内容重复退出不会产生重复任务，新轮次不会覆盖尚未完成的旧轮次。旧版检查点仍可恢复。成功只删除本次实际处理且内容未变化的文件；失败和取消的检查点保留。损坏或超大的常规文件会原子移到 `pending/quarantine/` 保留原件，当前内容再保存有效检查点，避免单个损坏待办永久阻塞退出；隔离或写入失败仍报告保存失败。记忆页面显示隔离数量，并说明可从原对话重新提取。打开工作区后恢复，长时间驻留时由原有空闲任务继续重试。自动提取关闭时不发起恢复请求，界面明确显示暂停，不承诺自动继续。

记忆提取窗口最多 80 条、序列化后 256 KiB，保留用户请求锚点和近期结果；单条超大文本只取摘录。提取前去除图片、私有推理和工具协议负载，保留用户/助手及其他 agent 的来源身份。完整聊天历史不受摘录预算影响。

向量建设在组批之前逐条排除已遗忘、被替换、失效及来源被屏蔽的内容。正常排除不作为服务错误，也不阻塞其他内容。发送和重试前继续检查实时策略，请求返回后再检查一次。写入向量时在同一 SQLite 事务内核对内容 hash 和 embedding 空间，避免把旧响应写到已修改的 chunk。

当前有效条目的检索副本还要与账本实时生成的内容或精确分块匹配（包括分块器生成的上下文前缀、重叠内容和自定义分块配置），不会通过简单剥离前缀放行任意内容。明确更正后的新内容即使包含旧句子，仍可正常索引和检索；历史摘要不享有此例外。整轮索引提交前再次检查策略，较早批次返回后发生的遗忘也会生效。

启动索引和搜索补索引共用策略检查与批处理逻辑。搜索补索引交给会话持有的后台任务，不等待文档向量请求，同一数据库的重复搜索合并处理；每批完成即校验并提交，正常慢响应不会因前台时间预算被取消。服务失败按 5、15、60、300 秒退避重试，无需新增聊天或再次搜索；退出时取消并等待后台任务，不产生脱离会话的 HTTP 请求。查询向量独立请求，已有合法向量继续可用。策略排除和服务故障分别记录，账本不可读时停止发送，不能降级为允许。排序、重排和最终返回都保留隐私过滤。

## 验证

- `pnpm test:memory-shutdown`：真实 Runtime 首次恢复收到无效模型结果，没有新增聊天时仍要自动重试；重试模型不返回响应，退出必须在三秒内完成、取消 HTTP 请求并保留检查点。
- `pnpm test:rust`：包含逐条隐私筛选、旧向量拒绝、合法向量保留、服务恢复、检查点恢复与取消清理等回归。
- `pnpm test`：包括待整理状态展示；`node scripts/validate-ui-surfaces.mjs` 检查页面布局与交互。

测试使用隔离数据和模拟服务，宿主测试的回环请求直接连接模拟服务，避免代理保留上游连接干扰取消断言。它们不替代 Windows、macOS、Linux 发布包各自的原生退出验收。
