# 录音转写工作台

主流程是选择声音来源、录制并增量显示原文、结束后自动整理纪要、在应用内回听和校对。页面不提供音频导入、服务选择或模型配置。

## 识别能力与边界

本版本复用已配置的 MiniMax `/v1/speech_to_text` 文件识别接口。对已可靠写入的 16 kHz 单声道 PCM 按短句生成 WAV 请求，安静边界优先切分，连续语音窗口最多约 4 秒；返回后追加已确认文字。接口响应时间另计，不承诺逐字即时返回。它没有把 SSE 文件识别结果误用成连续麦克风输入协议。

录音本身不要求网络或模型凭据。网络和服务暂时故障会保留音频和已确认文字，按退避策略重试，网络恢复事件会立即触发重试。连接缺失、凭据失效、接口不支持或额度不足时显示原因和设置入口，等待用户处理，避免把配置错误当作断网持续重试。配置修复后可以点击「重试转写」，在不中断录音的情况下更新连接并继续补转。增量识别游标只有在结果成功落盘后才前移；HTTP 错误和 HTTP 200 内的业务错误都不会跳过音频。暂停不计入音频时间轴。

结束录音首先保存本地文件，再补齐尾段并生成纪要。长时间积压使用已有的有界分片恢复，已确认的增量音频不重复提交。录音对象和完成任务位于 React 页面之外，切换页面不会中止它们；明确退出程序时优先保证录音保存，未完成处理可在下次进入时继续。

## 回听和校对

- 两个内容页签：会议纪要、转写原文。
- 点击纪要中的有效原文时间依据只定位，不自动播放；点击原文时间戳从该位置播放。
- 内置播放器支持进度、倍速、前后十秒及音量，只有失败时显示系统播放器备用入口。
- 音频通过仅授权会议 ID 与临时令牌的私有协议读取，支持 HTTP Range；单次读取不超过 2 MiB，不把多小时录音整体复制到前端。
- 校对草稿自动保留，显式保存后更新正式内容；冲突需要明确处理，不能静默覆盖。
- 修改原文保留已有纪要并提示核对，重新生成保留上一次纪要供恢复。
- 说话人标签以识别服务返回为准，不承诺跨短句的真实身份识别。
