# 电脑操作的任务体验

用户在普通对话中委托成果，过程进入现有“查看过程”，结束使用现有消息停止按钮，续接与修改要求通过普通消息。不存在独立任务栏、悬浮控制窗口或桌面专用的暂停/停止/继续按钮。

## 任务入口与消息归属

明确桌面任务自动接入原生与浏览器工具，用户不必先选模式。代码讨论、引用、历史加载和应用内容不授予执行权。目标来自宿主实际观察，歧义使用现有提问机制。

“继续”“接着完成刚才的任务”“标题改成会议记录”“继续，但不要发送”均为普通消息，前端不匹配继续关键词、不调用恢复接口。宿主进行保守意图准入，保存范围和补充约束，创建新 run、撤销旧引用并重新观察；提问与解释不恢复桌面写入。该准入是规则判断，不是任意自然语言语义的完备证明。

缺少消息正文时直接询问，界面显示“等待消息内容”，不先打开联系人或尝试发送。补充正文后保持同一 taskId；只说“继续”仍等待正文。明确正文作为字面内容保存，正文之外的补充约束进入任务范围。停止、解释或重启不抹掉仍缺少内容的状态。

任务状态携带 promptId，仅进入对应回复的执行过程。过程折叠不取消任务，也不轮询窗口截图。任务在宿主运行，不依赖页面组件挂载。浏览器连接与维护进入安全设置；改变连接前须通过现有停止入口结束当前执行。

## 执行与人工输入

| 情况 | 行为 |
| --- | --- |
| 单纯移动鼠标 | 不取消任务或动作 |
| 在其他应用打字、点击和滚动 | 应用定向动作继续 |
| 在同一目标应用操作 | 保守认定应用争用，取消当前动作子令牌；模型思考空档的输入同样锁定后续写入，不取消整项任务 |
| 争用动作结束后用户暂时停手 | 同 run 写入锁仍保留，不定时自动抢回 |
| 新的普通用户续接指令 | 创建新 run，重新观察后可恢复目标写入 |
| 必须前台的动作遇到其他应用人工输入 | 当前动作暂时让出桌面；不永久锁住整轮前台后备，其他后台目标可继续 |
| 点击现有消息停止按钮 | 撤销整项任务，取消模型、工具队列、浏览器和原生输入 |
| 应用重启或权限缺失 | 不自动恢复，保留上下文并说明缺失条件 |

macOS 使用 AX 直接动作/值设置、应用定向键盘事件及窗口单独捕获。不支持原生按下动作的控件和双击需要显式前台坐标路径；不派发未经实测可靠的后台鼠标事件。Windows 优先 UIA 直接动作；真实键鼠仍为前台。能力按动作与平台说明，不能承诺所有应用支持后台执行。原生输入监测不可用时拒绝写入；系统权限不能由模型代授。

自绘界面没有原生输入焦点时允许窗口级观察和绑定目标的视觉操作，不反复寻找不存在的控件。目标移到后台、窗口变化或图像过期时必须重新观察，不截取用户正在操作的其他应用代替目标。重复阻塞由宿主限次结束本轮，原消息显示原因和进度，用户通过普通消息续接。

## 状态与结果

正常进度使用“正在填写”“正在核验”“等待你确认”“已停止”“结果尚未确认”等语言。内部保留完整状态机，但不投射成常驻控制栏。模型轮次结束而缺少有效完成凭证时，撤销本轮执行权、保留待核验上下文；不能把没有文字输出当成仍在后台工作的证据。

工具派发成功、内容读回和整个任务完成分别记录。完成要求宿主核验凭证晚于最近写入。停止/冲突/超时期间已派发的动作不可回滚，先观察是否生效，禁止盲目重放发送、保存等动作。详情中的截图、操作和核验记录沿用已有工具展示，不再复制一份时间线。

## 验收边界

交互验收覆盖消息停止、普通对话续接、历史归属、折叠过程、主题与窗口尺寸；原生测试覆盖后台准备不激活、直接动作、冲突隔离、同 run 锁定和取消传播。Windows 实机、签名后 TCC、目标应用是否接受定向事件和真实模型跨应用成功率单独记录，不把接口/模拟通过外推为全平台实机通过。

实现与平台限制见 [控件说明](README.md)，实机与回归记录见 [验收](validation.md)。
