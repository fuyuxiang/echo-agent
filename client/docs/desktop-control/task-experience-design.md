# 电脑操作的任务体验

用户委托的是可核验的成果。正常流程是提出任务、观察进度、处理必要选择并获得成果；界面围绕同一任务组织聊天、实体操作与暂停续做，避免要求用户理解工具协议或分别恢复多个内部状态。

## 默认交互

- 明确的电脑任务在可信用户消息入口建立执行意图，真实 Runtime 选择 Computer Use 工具。代码讨论、否定指令、引用和普通文件生成不因出现应用名称而获得桌面操作权。
- 任务内的观察、定位、切换应用、原生控件、截图后备和指定保存连续执行，不按应用名称、按钮关键词或每个步骤重复确认。
- 系统自行选择合适的原生或截图方式。初次缺少系统权限时提供明确的设置引导，界面只呈现必要的结果进度与统一暂停/停止入口。
- 可信用户发送“停一下”同时取消模型和实体操作，并等待在途输入退出；发送“继续保存”等明确指令，在同一任务恢复并继续。可选“继续任务”入口发送同一次可信消息。
- 加载历史、网页、附件、工具输出、模型自身文本和讨论中的“继续”不能恢复执行。用户补充的保存路径、文件名和必要回答保留在原任务上下文。
- 完成时展示真实产物和位置。调用返回、文字读回与整个目标完成分别判定。

## 权限与关键选择

| 情况 | 约定 |
| --- | --- |
| 明确任务范围内的观察、输入、切换和指定新文件保存 | 连续执行，保留原生对象、焦点与取消检查 |
| 暂停后明确继续同一任务 | 撤销旧令牌，重新建立同任务同范围执行权 |
| 应用重启或桌面不可用 | 保留任务与成果；等待用户明确继续，历史加载不派发输入 |
| 系统权限缺失或设备锁定 | 给出具体处理入口，不能由模型代授系统权限 |
| 原请求未包含的关键选择 | 一次提出具体问题，回答直接接续原任务 |
| 未获授权的发送、付款、破坏性删除或覆盖 | 执行前展示目标与影响，取得针对性的确认 |
| 操作结果未知 | 先观察实际状态，避免重复副作用 |

任务范围不是操作系统文件沙箱。浏览器独立的网络/上传策略、其他 MCP 权限及明确拒绝规则继续生效。

## 状态、恢复与进度

运行中、等待必要输入、已暂停、已完成和无法完成由统一任务生命周期派生。模型一轮输出结束可能只是阶段反馈，不能清除未完成任务的授权状态或隐藏暂停入口。

暂停应说明用户接管、桌面不可用、重启或请求失败等实际原因。验收脚本的时限单独记录，不作为生产任务的隐藏期限或用户接管原因。后台恢复失败时保留暂停，不显示虚假的发送或恢复成功。

窗口、焦点、系统面板与过期引用优先通过重新观察原目标处理；目标变化或原生结果未知时，保留成果并说明未完成项。用户需要解锁、选择同名文件或确认覆盖时，提出具体下一步。

执行详情保留截图、控件、参数与诊断；主任务区使用“已填入正文，正在保存”等结果进度。生成间隙仍可暂停，失败提示说明正文或文件是否已经保存。

## 成果与回归

验收须覆盖明确任务直接启动、零重复审批、一次自然语言继续、暂停后实体输入停止、用户修改保留、准确的权限缺口及独立可读取的最终文件。实际控件值和文件正文都须与用户要求比较，不能只相信模型结论。

原生工具、引用和平台限制见 [控件说明](README.md)，真实模型与文件核验见 [桌面控制验收](validation.md)，效率口径见 [性能验证](performance.md)。不同应用与平台分别验证，不将一个合成文稿流程外推为任意软件可用。
