# 桌面任务运行时

桌面控制以一个会话绑定的任务串联原生应用、浏览器与已连接的结构化工具。前端、真实 ACP Runtime、认证的 `echoagent-automation` MCP 服务和原生执行器使用同一任务范围、取消边界与结果状态。实现覆盖 macOS AX 和 Windows UI Automation；不能将模块通过或接口存在等同于任意软件的实机成功率。

交互约定见 [任务体验](task-experience-design.md)，回归及实机方法见 [验收](validation.md)，性能口径见 [性能验证](performance.md)。

## 实现位置

| 层 | 主要实现 | 职责 |
| --- | --- | --- |
| 前端 | `ChatView.tsx`、`ExecutionProcess.tsx`、`ComputerExecutionDetails.tsx`、`BrowserTaskSettings.tsx` | 复用消息停止和过程详情；普通对话续接；设置中配对浏览器；无独立任务栏和悬浮控制窗口 |
| 会话与任务 | `src-tauri/src/automation/mod.rs`、`task.rs`、`checkpoint.rs` | 可信用户意图、任务与运行 ID、代次、权限、取消、成果凭证和私有检查点 |
| 目标与策略 | `targets.rs`、`policy.rs`、`desktop_coordinator.rs` | 已安装应用身份、真实目标确认、应用占用与物理桌面队列 |
| 原生 | `accessibility/{mod,helper,macos,windows,file_dialog}.rs` | 保留对象、AX/UIA、独立子进程、控件动作与系统文件面板 |
| 视觉与人工输入 | `computer.rs`、`emergency_stop.rs` | 窗口裁剪、坐标转换、局部图像校验、焦点与命中证明、分块取消、紧急停止 |
| 浏览器 | `browser.rs`、`browser_bridge.rs`、`browser-extension/` | 独立 Chromium 或已授权标签页、持续 CDP 连接、DOM/开放 Shadow DOM/可访问 iframe、分页、条件等待 |
| 独立成果核验 | `artifact.rs`、`document_verification.rs` | 明确任务路径下的 UTF-8 正文、Office/PDF 文本及 XLSX 缓存单元格只读核验 |
| 模型入口 | `commands.rs`、Runtime `AgentDefinition::computer_use` | 同一任务发现 browser/computer/MCP 工具，注入真实任务范围与当前执行上下文 |

## 任务、状态与授权

用户直接说明任务，例如“在文稿应用中填写这些内容并保存到指定位置”，由可信消息入口选择 Computer Use 工具配置并建立范围。代码讨论、否定、引用、历史回放和工具内容不能建立或恢复执行权。应用从任务与宿主观察解析；目标歧义通过现有提问解决，不要求先选择应用或操作模式。

未知应用的“打开/启动”请求先与宿主已安装目录精确匹配；“打开 README”等短文件名不会仅凭字数触发桌面模式。Windows 目录包含用户与系统 App Paths 注册信息、Windows/System32 的浅层 GUI 可执行文件，以及常见安装目录；已安装应用和运行中进程使用实际版本资源中的本地化名称及可执行路径建立同一身份。目录有数量、深度和读取预算，不宣称枚举任意安装位置。

macOS 已安装应用目录读取实际 bundle 的本地化名称、可执行名称、bundle ID，以及相同真实路径的运行中应用名称。搜索和启动范围匹配使用这些宿主别名，避免“微信”与 `WeChat.app` 的名称差异导致重复启动确认。模型提供的别名不能扩展授权；路径仍须来自实际目录并在等待后重新核对。

状态包括 `running`、`waiting_user`、`verifying`、`paused`、`stopped`、`completed`、`failed`、`result_unknown`。主程序保存任务 ID、运行 ID、范围、已绑定目标及最近 64 条元数据回执。检查点使用私有目录和原子替换，永不保存可恢复的执行授权；未完成任务在应用重启后从暂停恢复，旧控件、帧和执行令牌均不可复用。

“给某人发条消息”没有提供正文时先询问内容，宿主进入 `waiting_user/message_text_required`，拒绝桌面访问。普通回复补充正文后在同一任务继续；单独“继续”、停止再继续或重启不能跳过缺失内容。明确声明或引号包围的正文作为字面内容单独存储，后续指令另行追加到范围，正文中的“删除”“不要发送”等文字不会自行授予动作。缺失检查和消息意图仍是保守规则；不明确的复杂自然语言需要澄清。

同一任务的工具顺序执行。排队工具保留入队时的代次，暂停或新一轮任务之后不能携带旧请求执行。应用定向/原生控件操作不占用全局桌面队列；需要前台输入的动作独占物理桌面。对同一已识别应用的写入任务仍串行协调，等待人类决定时释放占用。系统面板的宿主与 AX provider 不同时，两者 PID 均进入冲突检查。

明确范围内的普通原生操作连续执行。目标来自宿主实际观察，不能用模型提供的应用名称冒充目标身份。请求已点名或用户已选择的应用可直接使用；新增范围外应用需要一次明确决定。针对实际控件名称识别到的发送、支付、删除、覆盖，只有任务已委托相应后果时才直接执行；明确禁止优先阻止，未委托则显示目标确认。终端和代理自身的桌面控制拒绝执行。其他 MCP/连接器仍采用各自权限。

后果判断保留同一条指令中的否定修饰和“先问我/确认后”等条件，只有新的可信补充指令才能覆盖旧限制。引号中的正文和声明的消息内容不能授予额外动作；文件路径中的动作词不能视为授权。规则不能证明条件已经满足时，进入真实操作确认。设置中的网络审批独立于任务生命周期，不改变已完成、已停止或已暂停任务的状态。

已有电脑或网页任务中的“发送之前先问我”等后续约束进入同一任务范围；“在 TextEdit 中继续保存”保留原任务路径和限制，不重建任务。消息正文中引用的“继续”只作为正文，不据此触发任务续接。讨论动作、补充正文或增加确认条件不能自行解除先前的明确禁止。

策略的后果识别基于已观察的控件语义，不是任意界面或任意快捷键的完整业务语义分类器。自绘界面、改写标签或复合快捷键仍可能无法自动识别业务后果，不能将其宣传为通用安全沙箱。

## 暂停、接管与取消

现有消息停止按钮使用统一取消入口，同时停止模型、文档事务与实体操作。没有额外暂停/停止/继续按钮，也没有独立悬浮窗口。消息按钮以任务执行权和模型状态共同决定是否可停止，而不只看文字是否流式输出。更换应用、配对或断开浏览器同样走并行取消，原生收尾不会挡在模型取消之前。先取消令牌，再等待原生执行退出，最后确认暂停。继续与改要求走普通消息入口（例如“接着完成”“标题改成会议记录”“继续，但不要发送”），前端不拦截“继续”也不调用恢复接口。可信用户消息重新建立执行权，保留任务范围并重新观察现场；不会在历史加载、确认卡过期或网络重连时自动恢复。

原生 provider 运行在同一可执行文件的 `--echo-native-helper` 子进程中。进入子进程模式发生在 Tauri 初始化之前；子进程校验 OS 父进程可执行文件，使用私有继承管道、随机握手、请求 ID 和有界 JSON 行协议。AX/UIA 对象只在子进程的所属线程中创建、调用和释放。父进程硬截止为 20 秒；取消通知后 750ms 未退出则终止并回收子进程，之后才释放原生操作持有的桌面租约。父进程异常退出导致私有管道关闭时，子进程也会取消并限时退出。未知结果不重放，下一步须重新观察。

在权限和平台允许时注册 Ctrl+Alt+Esc 紧急停止。macOS 事件 tap 和 Windows 键鼠 hook 区分代理标记的输入与人工输入；鼠标移动不触发取消；键盘、点击与滚轮按真实目标 PID 检查。后台动作只在用户操作同一应用时取消当前动作的子令牌；前台动作遇到人工输入会让出当前动作。任务令牌、模型和无关应用不会因此全局暂停。争用的目标在同一 run 中保持写入锁定，不会因 1.2 秒安静窗口结束而自动抢回；新的可信用户消息产生新 run 后才可继续写入。目标 PID 在模型思考和观察空档仍与 run 绑定，此时的同应用编辑也会锁定后续写入。近期输入用于动作开始前的拒绝，不是自动恢复计时器。宿主聊天界面的输入不视为接管。缺失输入监测时拒绝派发原生写入；监测和快捷键能力分别报告。系统锁屏、安全桌面、缺失系统授权均不自动绕过。

其他应用的近期输入只对需要物理桌面的当前动作返回暂时 `desktop_busy`，不会把整轮前台路径永久锁住。新 run 以可信消息准入时刻为界，不继承此前输入的争用状态。重复争用、无窗口、超时、失效引用、变化画面或无效完成凭证由宿主有界收敛，保留进度、撤销执行并在原消息展示具体原因，不允许模型靠重复查询无限维持“执行中”。

扩展接管另有 `Echo.pause` 确认：立刻改变连接代次，拒绝排队输入，等待已派发的单次 CDP 调用结束并 detach，然后回执。无确认则断开、保留暂停并要求重新连接及观察；不会改用其他登录环境继续操作。已派发到操作系统或浏览器的动作不能回滚，取消时保留“结果未知”的写入回执。

## 原生与视觉执行

`computer_context` 合并应用匹配、窗口、紧凑控件和实际菜单命令。已运行目标通过真实对象解析；`computer_installed_apps` 返回可启动目录，`computer_open_app({applicationId})` 只接受实际目录解析出的应用身份，兼容原有明确绝对路径。默认后台启动；`foreground=true` 可以重新打开已隐藏的目标窗口并确认前台应用。启动成功不等于窗口已可操作，仍须读取上下文。目录扫描有深度、数量与时限缓存限制，同名不擅自选第一个。

macOS 同名匹配包含主程序和其内嵌辅助 App 时，通过系统报告且已规范化的 bundle 路径识别 `主程序.app/Contents/...` 归属，排除同名内嵌辅助候选，并返回解析依据；没有硬编码微信进程名或 bundle ID。独立的同名应用仍保留歧义，精确辅助程序标识仍可访问。首次歧义观察不立即终止模型，允许读取/使用精确候选；连续无法消歧才收敛。

控件使用会话内短引用；操作前重新检查原生身份、窗口归属、文档位置、可见/禁用/受保护状态、焦点与取消令牌。动作附带新状态，模型直接使用它；完整快照、分页、查找、分段读取和条件等待继续可用。截断、虚拟内容和提供方错误显式返回。密码值不读取，密码焦点不接受工具输入。

优先调用控件 advertised action 或 `computer_set_value`。`inputMethod="keyboard"` 对真实文本控件进行应用内聚焦、原生 UTF-16 文本选区全选（不支持时用可取消的菜单/按键后备）、分块 Unicode 输入与完整读回；只核验本次值，不代替整个任务成功判定。显式 `trailingNewlines` / `expectedTrailingNewlines` 保留末尾换行需求。

窗口身份和键盘控件焦点分别观察；AX/UIA 没有输入控件焦点，不再阻止观察整个窗口、调用真实菜单或使用自绘界面的视觉路径。已知受保护焦点仍拒绝输入。

macOS 优先使用 ScreenCaptureKit 的精确单窗口过滤与系统录屏权限；异步捕获受 helper 硬截止约束。实测微信聊天主窗口可能被该静态接口遗漏，返回透明像素；此时使用公共 AVFoundation 视频输入，由系统在采集端裁剪到目标窗口，只取一帧，不录制音频或保存录像。该回退要求窗口处于前台、完全位于同一显示器内，并在捕获前后核对窗口 ID、PID、边界和全部重叠区域；外部可见或无法检查的覆盖窗口均拒绝，透明系统覆盖层须逐像素证明透明。同一应用的搜索浮层仅在原生窗口 ID、PID、AX 非模态对话框/浮动子类型、非主窗口状态、高于父窗口的层级及完全包含关系均核验后，才纳入父窗口画面和坐标命中；同 PID 的独立普通窗口仍拒绝。捕获前后浮层身份须一致。后台窗口不自动激活，返回 `foreground_required`，由任务显式选择前台路径。取得首帧后同步停止并清理回调；宿主停止仍可终止 helper。透明、空白或单色视频不能生成坐标帧；不以静态显示器截图补全透明窗口。连续无画面后保留进度并给出具体原因。

AX 坐标命中明确返回“未实现”时，使用 WindowServer 的真实窗口 ID、归属和前后层级核验；透明覆盖窗口须实际检查该位置的像素透明度，不能只按包围矩形认定遮挡。受限且无法检查的覆盖窗口保持拒绝。窗口 AX 代理重建时，只允许通过相同原生窗口 ID 和应用 PID 恢复窗口身份，普通控件不使用此后备。

`computer_screenshot({windowRef})` 绑定显式窗口，省略时只使用本任务最后明确观察的窗口；没有目标则要求先读取上下文。切换到其他应用会拒绝，不把新前台冒充目标。macOS 在一次 helper 请求中验证目标、捕获原生窗口并再次验证，再创建带真实窗口边界与缩放的输入帧。执行前重捕获同一窗口，检查身份、几何、整体和点击位置的局部像素；两秒内的一次性内部凭证才能输入。坐标点击在 helper 中重查命中对象；文字分块检查前台身份与取消，滚动先定位到验证过的窗口坐标。帧消费后失效。其他平台保留窗口与显示器交集的坐标转换。预览使用独立截图控制器，不消耗模型帧。

macOS 和标准 Windows 系统 Open/Save 面板可以使用 `computer_file_dialog({ref,path})`：有界准备路径/文件名并读回，不打开面板、不点击最终确认、不创建文件。Windows 适配标准 `#32770` 系统面板；第三方自绘文件选择器须观察其真实控件或接管。最终提交后仍须核验文件。

`computer_capture_window({ref})` 在 macOS 仅捕获已观察且唯一匹配的目标窗口，不激活应用、不退回整屏截图，不生成坐标输入 frameId。正常单窗口路径可用于后台观察；视频回退仅适用于满足可见性检查的前台窗口。PNG 和像素数均有上限，结果报告实际捕获后端。可输入的视觉路径仍要求目标在前台；不强行恢复焦点。

模型轮次结束但未提交有效成果凭证时，宿主撤销剩余执行权并保留“结果尚未确认”的任务上下文，不留下隐藏的运行状态。任务携带 promptId，界面只把当前状态挂到对应消息；历史操作记录保留在工具过程内。

## 浏览器与已登录标签页

电脑任务可直接混用 `browser_*`，不必切换会话模式。默认使用独立 Chromium 配置、网络代理和原有上传/下载策略。持续页面 CDP 连接减少重复连接；快照覆盖有限 DOM、开放 Shadow DOM 及最多 16 个可访问子 frame，返回范围、截断和 frame 失败。输出按约 11KB 分页，正文与控件共同保留到后续页，第一页不会被长正文挤掉所有控件；cursor 绑定目标、文档与时限且只可消费一次。元素引用绑定任务、标签页与观察到的文档代次，同 URL 重载也需重新观察。

`browser_wait_for` 对真实 URL、元素出现/消失或精确文本做有界等待。`browser_wait` 只是延时，不产生成果凭证。iframe 的不可访问上下文、复杂变换和 closed Shadow DOM 不视为完整可操作范围。

在设置 → 安全与权限 → 任务浏览器中连接已登录浏览器；运行中的任务须先用消息停止按钮结束。配对会撤销旧执行，返回五分钟有效的 loopback 配对地址及已随程序打包的扩展目录。在 Chrome/Edge 的扩展管理页加载目录，打开扩展，粘贴地址并勾选允许控制的标签页，再在任务中继续。扩展无需网站 content script；浏览器显示 debugger 提示。

设置显示等待连接、已连接、断连和地址过期状态，提供地址复制、重新生成以及“使用独立浏览器”入口。取消配对或不再使用扩展时，可主动切回任务独立浏览器；该操作先撤销旧运行和连接。意外断连不会自动切换登录环境。浏览器来源变更与新任务准入按会话串行，防止旧配对晚到后覆盖新的选择。

桥接校验精确 loopback Host、不可猜配对码和 extension Origin。扩展只接受自身 popup 的配对消息，校验所选 HTTP/HTTPS 标签页；协议只允许本项目实际使用的 CDP 方法。替换、断开或浏览器撤销 debugger 会使旧连接失效。停止只 detach，不关闭用户标签页或清理用户登录。扩展使用用户浏览器自己的登录、扩展和网络环境，不能宣称具有独立浏览器代理的子资源网络隔离或私有下载捕获。

此差异在配对前的设置中明确说明。独立浏览器的“允许访问本机与内网”覆盖页面及子资源；扩展模式改为“允许导航到本机与内网页面”，只限制代理主动导航地址，网页自身请求沿用原浏览器权限。网络审批也使用对应说明。数据清理明确仅针对独立浏览器，不清除用户浏览器中的登录、缓存或下载。

## 成果与回执

回执明确区分观察、输入已派发、局部读回已核验、结果未知和任务成果已核验。写操作的取消或传输超时不被当作“确定未执行”；执行过程及工具卡保留结果待核验。前端不会把 MCP 传输结束的“completed”直接显示为实体任务完成。取消未结束的写入会留下未知回执；旧运行返回的晚到结果不能覆盖新状态。

- `computer_verify_file`：只读用户任务明确指定的文件；精确 UTF-8 正文和结尾核验才可作完成凭证，单纯存在不够。
- `computer_verify_document`：只读明确路径的 DOCX/XLSX/PPTX/PDF；核对要求的文本片段及 XLSX 指定 sheet/cell 的缓存值。拒绝链接文件和超限内容，压缩包条目、单项及总解压量均有界。
- `computer_wait_for`、`browser_wait_for`：真实条件满足后产生对应凭证。
- `computer_verify_visual`：macOS 对新捕获的目标窗口区域执行本机 Vision OCR，核对正向文字条件。区域使用截图左上角的归一化坐标；核验发送结果时分别选择会话标题和消息记录区域，排除输入框与联系人列表。匹配仅忽略空白/换行，保留标点；低置信度、截断、错误区域、窗口变化、取消或不匹配不产生完成凭证。期望文字不作为 OCR 提示词，不能靠模型断言通过。只证明截图时指定区域的可见文字，不证明服务器投递或已读状态。Windows 暂未提供该 OCR 路径。
- `automation_complete({evidenceIds,summary})`：只接受本任务实际核验工具的凭证，并要求它们晚于最近的写入；模型自行填写 `verified` 或引用旧结果不能完成任务。完成撤销执行权。

凭证证明用户提供条件的核验结果，不自动证明所有未声明需求。Office/PDF 核验不覆盖排版、视觉质量、公式重算、宏或云端投递；云端结果仍须观察相应服务的真实状态。桌面应用以当前系统用户运行，任务工作区不是 OS 文件沙箱。

## 平台限制

- macOS：需要当前运行应用的辅助功能与屏幕录制授权、可用图形会话。150ms AX 超时加外层进程硬截止；签名或安装路径变化须重新核对系统授权。
- Windows：需要交互桌面；UIA MTA、connection/transaction 超时和 helper 截止共同生效。UAC、安全桌面、高完整性窗口与 provider 缺口不可绕过。未提供完整的注册表/UWP 应用目录或通用 `documentUrl`。
- macOS 原生快捷键和文字替换使用菜单动作/进程定向键盘事件，单击使用控件 advertised AXPress，不自动激活窗口，也不移动全局指针；应用不支持后台焦点/输入时明确失败，不偷偷退回全局输入。Windows 的 UIA 原生动作/值设置可直接寻址；键盘、双击及坐标后备仍依赖前台。没有 AXPress 的控件及双击不派发后台鼠标事件；须显式激活窗口，重新截取前台画面后使用受保护坐标输入。各应用是否接受定向键盘事件须实机验证，不能声称所有软件均可后台操作。
- 原生冲突目前按应用 PID 判断，尚未细分为同一应用中的不同文档/控件；同应用人工操作可能保守地阻止该应用的当前写入。已派发的事件不能撤回。扩展浏览器目前依赖页面变化校验与 debugger 断开/停止确认，尚无等价的 PID 输入锁，同时人工编辑受控标签页仍存在竞态。
- 已安装应用目录只扫描已配置标准位置及有界层级；自定义目录和平台打包应用可能不在目录中。
- macOS 原生窗口帧使用系统报告的窗口边界与实际图像尺寸；显示器截图路径保留原点和缩放，跨屏窗口取选中显示器交集。混合 DPI、窗口动画、屏幕外区域及长期多屏稳定性需实机单独验收。
- Linux 没有本项目要求的原生焦点/命中保护，完整桌面任务不可用；底层 X11 代码保留不代表新安全路径的功能承诺。
- closed Shadow DOM、自绘/游戏/远程桌面、虚拟化内容和不可访问 iframe 不保证控件覆盖。条件核验和 UI 后果识别均非通用业务证明。
- 扩展当前为随包提供的未上架 MV3 目录，需要用户主动加载与配对；实际 Chrome/Edge 安装、签名后权限、Windows 实机与长期任务成功率须分别验收。
